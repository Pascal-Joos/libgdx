So the nullability of params.textureData is exactly the nullability of Texture.getTextureData().

In libGDX’s Texture implementation:

- A Texture is always constructed with a non-null TextureData (either provided explicitly or created internally from the file, pixmap, etc.).
- That TextureData is stored and later returned by getTextureData().
- TextureData is required for uploading/reloading the texture to OpenGL; this same method (invalidateAllTextures) calls texture.reload(), which in turn relies on the texture having valid TextureData.
- There is no standard libGDX code path where a Texture exists but its internal TextureData is set to null; doing so would break reload(), and libGDX’s own implementations do not do this.

Given normal/libGDX-intended usage (i.e., textures created via the standard constructors and not via custom subclasses that override getTextureData in a broken way), texture.getTextureData() is guaranteed non-null, thus params.textureData is non-null, and the call:

- Someone provides a custom Texture subclass that overrides getTextureData() to return null, or
- Someone manually manipulates internals in a nonstandard way (e.g., reflection) to clear the TextureData.
